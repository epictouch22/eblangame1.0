EBLANGAME V6.4 — CLIENT UPDATE INTEGRATION

Проверен Client Update.pdf. Исходный фрагмент нельзя было вставлять напрямую:
- он использовал другой контракт клиента (Room/Socket/Button, room.state, start_game);
- в текущем проекте режимы запускаются через game:select/game:start и живут в room.game;
- для новых режимов в архиве не было серверной логики и Socket.IO обработчиков;
- «Один пиксель» из PDF отправлял draw_event/time_update/clear_canvas, которых сервер проекта не обслуживал;
- приватные роли/слова нельзя безопасно хранить в общем room state.

Что сделано:
1. Добавлен режим «САМОЗВАНЕЦ» целиком на клиенте и сервере.
   - минимум 3 игрока;
   - 3 раунда;
   - слова выбираются парами из одной широкой категории, но заметно отличаются;
   - роли и слова отправляются каждому игроку приватным Socket.IO событием;
   - ассоциации идут по очереди;
   - затем тайное голосование;
   - если самозванец пойман, у него 30 секунд на последнюю догадку;
   - начисление очков и переходы между раундами.

2. Добавлен режим «ОДИН ПИКСЕЛЬ».
   - общая тема;
   - общий синхронный холст;
   - один жест за раз и серверная перезарядка 1,3 секунды;
   - кисть, ластик, линия, квадрат, круг, треугольник, палитра и размеры;
   - возможный вредитель получает приватную тайную задачу;
   - 60 секунд рисования, пауза/скип работают;
   - голосование за вредителя или вариант «вредителя не было»;
   - сервер считает результаты и очки.

3. Обновлены типы режимов, рулетка, выбор режима и обработка выхода игроков.
4. Добавлены стили новых экранов в стиле текущего Eblangame.
5. Активные файлы проекта: client/src/main.tsx, client/src/style.css, server/src/index.ts.

Проверки:
- TypeScript syntax/transpile: OK для клиента и сервера.
- Дополнительная проверка типов с локальными заглушками зависимостей: OK.
- Полный npm build в контейнере не запускался, потому что npm install не смог получить пакеты из registry в доступное время. На Render зависимости ставятся buildCommand-ом проекта.
